## 前端重构：睡莲池皮肤 + 无构建 ES Module 拆分

- 问题：`templates/index.html` 长到 1333 行（CSS 455 + HTML 78 + JS 787、30 个函数、13 个接口），改一处要在一个文件里翻；同时定稿的"睡莲池"设计稿要落到页面上。
- 原因：单文件内联 style/script 的写法撑不住这个体量；三个全局传输变量（`currentTransfer`/`xhrs`/`fileId`）被并发传输互相覆盖过，"上传中点下载再点取消"会用残留 `file_id` 误删正在上传的分片。
- 解决方法（方案与逐条决定见 [`frontend-refactor-spec-2026-09-21.md`](frontend-refactor-spec-2026-09-21.md)）：
  - `templates/index.html` 1333 → 164 行，只留标记；样式拆 `static/css/tokens.css`(95)/`pond.css`(161)/`ui.css`(467)，脚本拆 `static/js/` 12 个原生 ES Module，`main.js` 按 hud→files→upload→download→clipboard→login 顺序 `init(ctx)`，无构建、无框架、无 npm 依赖。
  - 内联 `onclick` 全部去掉（模块作用域函数不在 `window` 上），列表行用 `#file-list` 事件委托；文件名只经 `data-filename` + `textContent` 进 DOM。
  - 单传输闸门 `transfer.js`：`acquire(kind, username)` 返回 token 或 null，token 自带 `xhrs/cancelled/fileId/timer`，清理只认自己的 token；取消按钮活在活跃行的 `.fp-meta` 里，传输结束即移除；`beforeunload` 有传输时提示确认。
  - 后端两处改动：`_request_end` 的 no-cache 条件并上 `/static/`（防止换皮肤后拿到旧 js）；`list_files` 返回 `mtime`（新 UI 文件行要显示修改时间）。上传/下载协议一个字没改。
- 日期：2026-09-21
- 验证：临时实例 5001（未占 5000）。`py_compile` 过，12 个模块逐个 `node --check` 过；`curl -sI /static/js/main.js` 得 200 + `Cache-Control: no-cache` + ETag。实测：1.00 GB 上传 15.37s = **66.6 MB/s**（4 路并行，行内进度"上传 · 74.4 MB/s · 剩余 25秒 · 分片 6/64"）；200 MB 上传后合并耗时 0.46s；19.5 KB 分片下载走通（`/api/download/chunk` 206）；200 MB 分片下载在 32.0 MB/200.0 MB 处被本机 IDM 的浏览器集成截走，页面收到 IDM 自造的 `HTTP 204`（服务端日志仍全是 206）——非代码缺陷，见"平台坑"，多分片下载与 >1GB 原生下载待关 IDM 后复测。取消上传→后端 `上传已取消` 日志 + `.chunks/` 清空（并暴露 R4-P1-1 竞态）；传输中点另一行下载被闸门拦下；批量 3 文件混合成败聚合提示正确；哈希弹窗 4 条校验命令 + 4 条下载命令、自动全选、ESC/遮罩关闭、背景锁滚动；`<img src=x onerror=alert(1)>.txt` 上传不执行脚本（Windows `OSError 22` 拒建档，前端提示"合并失败，详情见服务端日志"）；剪切板保存/复制/刷新/清空（含 HTML 样式文本原样）、登录/记住我/刷新后 autoLogin/切换用户后列表与磁盘条同步。

## 下载两条分支复测（关掉 IDM 浏览器集成）+ 登录页落地

- 问题：上一轮 200 MB 分片下载在 32 MB 处报 `HTTP 204`、>1 GB 原生下载分支没有数字，P3 未验收。
- 原因：本机 IDM 的浏览器集成接管带 `Range` 的 XHR，页面侧拿到它自造的 204（服务端日志仍是 206）。
- 解决方法：用户关闭 IDM 集成后复测；同时按设计稿 `QFS · 登录.html` 把登录占位面板换成整屏登录台——新增 `static/css/login.css`（350 行，规则全部收在 `#login-gate` 作用域内，不与主页面同名 `.eyebrow`/`.qtitle` 冲突），`templates/index.html` 的 `#login-gate` 换成 `.backdrop` 三层蒙版 + 拱框展品 + 宣纸登录卡 + `.wash` 揭示层（219 行），`login.js` 驱动转场时序（提交 → 按钮 loading(0) → 卡片 `is-leaving` + 拱框 `awake`(520ms) → 圆形揭示(950ms) → 收幕(1680ms)），登录台的显隐从 `main.js` 移交给 `login.js`（`main.js` 只管 `#mainGrid`），退出登录时 `resetStage()` 复位类与按钮。用户名输入框 `maxlength` 16 → 32（后端 `_USERNAME_RE` 上限 64），空用户名不再回退 `default`，改为设计稿的报错抖动"请输入用户名"。
- 日期：2026-09-21
- 验证：200 MB 分片下载走通，7 个 `/api/download/chunk` 全 206，页面计时 **1.07s、平均 188.9 MB/s**，落盘 `Downloads/dl-200mb.bin` 209715200 字节；>1 GB 分支前端判定正确（1.20 GB 提示"已交给浏览器下载管理器"），`curl -H "Range: bytes=0-1073741823" /api/download` 得 206、1.00 GiB / 9.28s = **110.2 MB/s**（自动化会话里浏览器未落盘，需用户在自己浏览器点一次确认）。登录台：桌面 1280 与移动 390 截图核对版式；空提交出 `.invalid` + 报错文案；提交后 700ms `is-leaving/awake/is-loading`、1300ms `wash.revealing`、2000ms 登录台 hidden 且文件列表 5 行就绪；勾选记住我后 `localStorage.clipboard_last_user=pytest9`，刷新直接跳过登录台（无转场）；退出后登录台复位、`body.login-pending` 重新锁滚动。12 个模块 `node --check` 全过。

## A1：登录台与主页面共用一层背景

- 问题：登录 → 主页的转场"太不丝滑"（用户原话）。两态各带一张池面图，切换瞬间背景互换 + 蒙版硬切，画面跳一下。
- 原因：`#login-gate .backdrop > img` 自带一张 `monet-pond.jpg`，与页面顶部 `.bg-layer` 是两层独立背景；`.wash` 金幕的 `clip-path` 动画只扩圆、自身不透明，收幕时是硬切而不是溶解。
- 解决方法：整站只留 `pond.css` 的一层 `.bg-layer`，登录态不再自带图。`<body>` 加 `data-stage="login|app"` 作为唯一开关：登录态把 `.page`、`.bg-mist`、`.bg-vignette` 压到 `opacity: 0`，登录台只在共用池面上叠三层 `.veil` 蒙版加深画面；`login.js` 在 950ms（金幕铺开那一刻）翻 `data-stage`，主页面 `.62s` 淡入与登录台 `.portal`/`.site-foot`/`.backdrop` `520ms` 淡出同时发生在幕布底下；`@keyframes lbPortalReveal` 改为 62% 起把自身 opacity 拉到 0（溶解），删掉 `.backdrop > img` 相关规则与 `lbBgIn`/`lbPondDrift` 两个关键帧。
- 日期：2026-09-21
- 验证：脚本在转场过程中采样 computed style——t=0/200/520/700ms `stage=login`、`.page` opacity 0；t=981ms `stage=app`、wash `circle(0%)` 圆心 x=480.5px（拱框中心）；t=1209ms page .88 / 蒙版 .07 / wash `circle(128%)`；t=1504ms page .999 / 蒙版 0 / wash opacity .22（正在溶解）；t=1707ms 登录台 hidden、page 1。全程无背景互换、无硬切。DOM 里 `.bg-layer` 与 `monet-pond.jpg` 各只有 1 个。

## B1：剪切板换成全员共享的留言板（SQLite）

- 问题：`clipboards/<user>.txt` 每人一份、后保存覆盖先前，看不到别人贴的东西；设计稿 `qfs-waterlilies/` 画的是多条消息流。用户要求：改名留言板、全员同一块板、文件仍按用户隔离、页面只留最近 5 条、更早的进数据库不展示。
- 原因：存储按用户分文件 + 单条覆盖写，没有消息表，也没有"跨用户可见"这个概念。
- 解决方法：
  - 后端换标准库 `sqlite3` 单文件 `clipboards/messages.db`，表 `messages(id INTEGER PRIMARY KEY AUTOINCREMENT, author, device, ts, text)`，`journal_mode=WAL`、`timeout=5.0`、`_board_lock` 串行化 INSERT。新增 `GET /api/board?username=&after=`（返回最近 `BOARD_VISIBLE=5` 条 + `latest_id` + `total`，`after` 命中最新时 `unchanged: true`）与 `POST /api/board`（body `{username, text, device}`，text 非空且 ≤2000 字符，device 过 `normalize_device`：压平空白 / 去控制字符 / 限长 24）。删除 `GET|POST /api/clipboard` 及 `get_clipboard_path` / `read_clipboard` / `write_clipboard`。
  - `init_board()` 在启动时建表，并把旧 `clipboards/<user>.txt` 各迁成一条历史留言（author=原用户名、device=`旧剪切板`、ts=文件 mtime），原文件改名 `.migrated` 留在原地；多进程同时启动靠 `os.rename` 的原子性去重。**（这段启动期兼容迁移次日按用户要求删除，改为一次性脚本导入，见 [`2026-09-22.md`](2026-09-22.md)）**
  - 前端 `static/js/clipboard.js` 更名重写为 `board.js`（模块数仍是 12）：`#clip-list` 消息行（`author · device` + `MM-DD HH:MM` + 复制按钮）、5s 轮询带 `after` 增量、发送后 `load()` 而非 `reload()` 以保留 `latestId` 让新行打上 `.fresh`、`looksTechnical()` 命中的行走等宽（URL / 命令 / 多行）、`visibilitychange` 隐藏时停轮询。`api.js` 收口为 12 个接口（`board` / `sendBoard` 替换原两个 clipboard 接口）。样式沿用设计稿 `.clip` 行 + 圆角 `#clip-input`，≤560px 时 `.sendrow` 竖排。
- 日期：2026-09-21
