## 弹窗右上角的关闭 × 突兀粗糙

- 问题：文件信息弹窗与删除确认框的关闭钮是"描边小胶囊里塞一个文本字符 `&times;`"——字符字重和垂直居中随字体渲染波动，与全站 1.5 描边 SVG 线条图标不是一套语言；`padding: 2px 11px` 把胶囊挤得变形，hover 还跟着 `.qbtn` 上浮 1px，角落小按钮抖动显得廉价。
- 原因：初版直接复用了 `.qbtn` 按钮组件，只把文案换成 `×`，没有独立的关闭钮样式。
- 解决方法：两个弹窗的关闭钮去掉 `.qbtn` 类，内容换成 14×14 SVG 叉（两条 line，stroke-width 1.6、round cap、currentColor）；`.modal-close` 重写为 30×30 无边框幽灵圆钮——默认 `--ink-faint` 近乎隐形，hover 变 `--gold-glint` 并点亮 `rgba(var(--rgb-gold), .1)` 圆底（反馈靠点亮不靠描边位移），active `scale(.92)`，focus-visible 沿用 2px 金 outline；`.modal-head` 的 `align-items` 从 flex-start 改 center，叉与 17px 衬线标题同轴。
- 日期：2026-09-25（298af38）
- 验证：5001 临时实例浏览器实测——默认态细线叉、hover 态金色圆底点亮截图确认；点关闭实际关窗（`hashModal.hidden=true`，300ms 收幕）；测试用户 uicheck11 的文件与目录已删，实例已杀。check_dead_css 139 选择器零死规则。

## 上传中断在服务端无记录（C-0925-1，原 R3-P1-4/A-0925-1）

- 问题：上传中断没有痕迹——abort 日志只有 file_id 没有文件名/进度；客户端半途消失（关页/断网）时 waitress 在协议层就丢弃请求，应用层零落点（2026-09-19 实测：声明 1000000 字节实发 1000 后断开，无文件无日志）。24h 后清扫只报"清理了 N 个目录"。
- 原因：分片请求不带文件名；清扫/取消日志不带内容信息。"实时记录中断"做不到，只能"记成对"。
- 解决方法：分片请求 query 加 `&filename=`（过 `safe_filename`，仅进日志与 `meta.json`，绝不拼路径）；首片落盘写 `meta.json`（文件名+开始时间）并记 INFO「上传开始」——"只有开始没有合并完成"即中断签名；`merge_chunks` glob 从 `*` 收窄成 `chunk_*`（否则 meta.json 混进序号解析 IndexError→500）；abort 与 `sweep_stale_chunks` 删目录前读 meta.json，sweep 逐条 INFO「清理未完成上传: user/file_id/file/分片数/已收字节/最后写入」。sendBeacon 上报线未做（未实测、前两条已覆盖排查需求）。
- 日期：2026-09-25（b9315a0）
- 验证：5001 实例——70MB 双分片中文名文件：日志「上传开始: user=uicheck12 file=中文测试.bin file_id=t1file」、目录含 meta.json、merge 成功；残留目录 mtime 造旧 25h 后：「清理未完成上传: … file=中断演示.bin 分片数=1 已收=976.56KB 最后写入=2026-09-24 13:15」；abort 日志带 file=取消演示.bin。（测试实例用 `python -c import` 起，`__main__` 里的启动维护线程不跑，sweep 为进程内直调验证）

## /api/file/hash 同步整读文件占请求线程（C-0925-2，原 R3-P2-6/E-0925-2）

- 问题：无哈希记录时该接口在请求线程内整读文件（30GB 占住 8 个 waitress 线程之一数分钟）；运行中手动放入/原地替换的文件在下次重启对账前都无记录，第一个点它的人触发同步整读。
- 原因：计算写在请求路径里；运行期没有主动补算，只有启动对账。
- 解决方法：常驻守护 `hash-worker` 线程 + 队列串行补算（hashlib 计算时释放 GIL，与请求线程真并行；空闲就是一个阻塞线程，零 CPU）；`/api/files` 每次 listdir 把无有效记录的文件搭便车入队；`/api/file/hash` 无记录改为入队 + 返回 `computing: true`，**同步整读从请求线程彻底移除**（比原方案"保留同步兜底"更进一步：hash 请求本身就是入队时机，兜底分支永远轮不到）；前端弹窗每 3s 轮询，`reqId` + `modal.hidden` 双守卫防串窗；落记录复用 `record_hash` 的锁内重读合并。
- 日期：2026-09-25（b9315a0）
- 验证：手动放 1.4GB → 首请求 `computing:true`，worker 1.37s 算完；手动放 6GB（冷缓存）→ worker 6.98s，浏览器弹窗 0.5s 时显示「服务端正在计算校验码…每 3 秒自动重试」、13.5s 时自动填入 `0fb2531d…` 并全选；列表加载即触发补算（点之前哈希常已就绪）。测试用户 uicheck12（含 6GB 文件）已删，实例已杀。
