## 复制给别人的地址带 localhost，接收端连不上

- 问题：文件信息弹窗「命令行下载」的 URL、顶栏地址芯片的显示与复制，都取 `location.origin`。本机用 `http://localhost:5000` 打开时，复制出去的是 localhost，接收端电脑连不通；芯片显示的也是 localhost。
- 原因：前端只知道自己地址栏里的地址，局域网 IP 只有服务端拿得到。后端已有 `get_primary_lan_ip()`（UDP connect 探默认路由出口 IP，不真发包），但只用在启动横幅。
- 解决方法：后端加 `GET /api/server-addr` 返回局域网 IP（先 `get_primary_lan_ip()`，为空退 `get_lan_ips()` 第一个，都没有返回 null）。api.js 加 `shareOrigin()`：hostname 是 localhost/127.0.0.1/[::1] 时请求该接口替换主机名，否则原样返回地址栏 origin。弹窗下载命令、顶栏复制、芯片显示文字三处都改走它；弹窗提示文案改为说明自动替换。
- 日期：2026-09-24（5c69c61）
- 验证：5001 临时实例 `curl /api/server-addr` 返回 `{"ip":"198.51.100.7"}`；浏览器实测芯片显示 `198.51.100.7:5001`，弹窗 curl 命令里是 `http://198.51.100.7:5001/api/download?...`。

## 弹窗里的下载命令被省略号截断

- 问题：「命令行下载」的 curl/aria2 命令带长 URL，行尾出现 `…`，看不到完整命令。
- 原因：ui.css 给 `.verify-cmd code` 写了 `white-space: nowrap; text-overflow: ellipsis`——单行显示是旧设定，命令本来就该看全。
- 解决方法：`.verify-cmd code` 改为 `overflow-wrap: anywhere`（去掉 nowrap/ellipsis），URL 无空格也能折行，复制按钮保持右侧。
- 日期：2026-09-24（5c69c61）
- 验证：浏览器实测弹窗内每条 curl 命令折成 2~3 行完整显示。

## 登录留空报错，与换用户弹层行为不一致

- 问题：登录页用户名留空提交报「请输入用户名」并抖卡；顶栏换用户弹层早已是"留空 = default"，两个入口行为不一致。
- 原因：login.js 的 submit 里做了空值检查弹错误，弹层那边是 `trim() || 'default'`。
- 解决方法：submit 改为 `input.value.trim() || 'default'`；删掉随之无用的报错链路（showError/clearError、index.html 的 loginError 节点、login.css 的 `.field.invalid`/`.err`/`.login-card.shake` 规则与 lbShake 关键帧）；placeholder 改为「输入用户名，留空 = default」。
- 日期：2026-09-24（5c69c61）
- 验证：浏览器实测空提交后 `body[data-stage]=app`、头像 `de`/title `default`；check_dead_css 零死规则。

## 文件行哈希只显示 12 字符，右侧空白没用上

- 问题：文件行第二行的 SHA-256 在 JS 里写死只取前 12 字符；`.fmeta` 本就 flex:1 占满整行宽，哈希和右侧「下载」按钮之间永远空着一段。
- 原因：显示长度在 JS 里写死，没利用行宽。
- 解决方法：完整 64 字符哈希进按钮文本，title 给完整哈希。第一版把哈希按钮留在原结构里靠 `.fsub` 的 ellipsis 截断——**失败**：哈希是 `<button>`，Chrome 对 button 强制 `display: inline-block`（写 `display: inline` 计算值仍是 inline-block），inline-block 在 nowrap 容器里不可分割，剩余宽度放不下时整个按钮被裁掉、只剩一个省略号，比改之前更糟。最终版：`.fsub` 改 `display: flex; min-width: 0`，前缀"大小 · 时间 · "包进 `.fsub-pre`（flex:none），哈希按钮 `flex: 0 1 auto; min-width: 0` + 按钮自身 `text-overflow: ellipsis`（实测 Chrome 支持在 button 内部渲染省略号）。
- 日期：2026-09-24（5c69c61）
- 验证：浏览器实测 1794px 宽显示到 `SHA-256: 934e880bcb1f2fd856fa995ef5c945c3…`（铺满到下载按钮），1000px 宽同一行提前截断仍铺满，自适应成立。

## 拖文件放到文件库面板外，页面被浏览器打开文件顶掉

- 问题：拖放上传的投放区原来只有文件库面板。拖文件在标题区、留言面板、页面空白处松手，浏览器默认行为是直接打开该文件，整个页面被顶掉，看起来像拖放上传坏了。
- 原因：initDrag 只把 dragover/drop 绑在 `#files-panel` 上，面板外没有 preventDefault。
- 解决方法：改绑 document：`dataTransfer.types` 含 Files 且已登录才 preventDefault 并点亮新增的全屏提示层 `.drop-veil`（文案「松开鼠标 · 上传到文件库」，pointer-events: none）；drop 取 `dataTransfer.files` 走现有 `uploadFiles()`；dragleave 仅在 relatedTarget 为 null（拖出窗口）时收层。删掉随之冗余的面板金边反馈 `.panel.dragover`，上传按钮 title 改为「可多选，或拖到页面任意位置」。
- 日期：2026-09-24（5c69c61）
- 验证：py_compile、12 个模块 node --check、check_dead_css.py 全过。

## 删文件确认还在用浏览器原生 confirm()

- 问题：全站最后一处原生弹窗是删文件的 `confirm()`（files.js）——浏览器默认灰框与睡莲皮肤不符；且同步阻塞，点完"确定"后删除失败也无法回头，只能吃一个 toast。
- 原因：ui.js 早有通用 modal 机制（遮罩/Esc/Tab 焦点圈定/焦点归还），但这一处一直没接上。
- 解决方法：ui.js 加 `confirmDialog({title, body, okText, cancelText, onOk}) → Promise<boolean>`，复用 modal 骨架；`openModal` 加第三个可选 onClose 回调（Esc/遮罩/取消关闭 = resolve false），新增 `modalLocked`——onOk 请求期间锁死关闭路径，onOk 返回 false 或抛错则窗保持打开、按钮恢复可重试。index.html 加唯一的 `#confirm-modal`：`.modal-box.sm`（420px）、正文 `textContent`（文件名不拼 innerHTML）、按钮复用 `.qbtn`/`.qbtn.danger`/`.qbtn:disabled` 现成样式；打开时焦点落「取消」防误按 Enter。files.js 的 removeFile 改走 confirmDialog，删除逻辑挪进 onOk。
- 日期：2026-09-24（298af38）
- 验证：5001 临时实例 + 浏览器实测四条路径：弹窗外观与焦点在「取消」✓；Esc 关窗、行不变 ✓；服务端先删掉目标再 UI 删除（success:false）→ 窗保持打开、按钮恢复 ✓；确认删除 → 关窗、行移除 ✓。测试用户 uicheck10 的文件与目录已删，实例已杀。
