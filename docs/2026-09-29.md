## 校验码弹窗拿到值后回写列表行（C-0929-1）

- 问题：服务启动期间往 `files/` 拖入文件后，列表那一行一直显示"校验码未记录，点击计算"；点开弹窗能看到 SHA-256，但行的文字不变。`logs/app.log` 证据：`16:17:48 后台计算校验码: file=2.重叠数据.zip size=334.43MB` 与同一秒的 `后台校验码完成 … sha256=1bb68a72… 耗时=0.40s` 是 hash-worker 打的，且前面**没有** `/api/file/hash` 的「校验码未就绪」——说明入队来自列表接口的搭便车入队（`http_messages_share.py:991`），哈希在列表响应之后 0.4 秒就落库了，行却没跟着更新。
- 原因：行内文字只在渲染时按 `sha256` 有无二选一（`static/js/files.js` 的 `makeRow`），渲染后没有任何回写路径。列表刷新只有三个触发点（切用户 `main.js:32`、上传结束 `upload.js:106`、下载结束/失败 `download.js:66-67`）；弹窗自己的 3s 轮询结果只写进弹窗输入框，不碰列表 DOM。凡是"渲染之后才落库"的哈希都会停在旧文字——外部拷进 `files/` 的文件、算 7 秒的 5.6GB 大文件（`六G.bin` 实测 7.43s）同样。
- 解决方法：`static/js/files.js` 抽出 `setHashBtn(btn, sha256)`（渲染与回写共用），新增 `updateRowHash(filename, sha256)`；弹窗轮询拿到值后调它回写对应行。行匹配用 `dataset.filename` 逐个比对，不拼 CSS 选择器（文件名带引号也不会炸）。行文字变 `SHA-256: …` 并去掉 `fresh` 类（淡紫"待算"样式随之消失）。
- 日期：2026-09-29（14565ab）
- 验证：
  - `node --check static/js/files.js` 通过。
  - 5001 临时实例 + 一次性用户 `pytest_hash` + 30MB 随机文件（无哈希记录）实测两条路径：①记录已在库时点按钮，弹窗与行同时出值；②外部把 `.hashes.json` 清空后点按钮，日志 `16:25:32 校验码未就绪，转后台计算` → `16:25:35` 3s 轮询拿到值，行更新为 `SHA-256: 983836100a2ad04c3bc7d4f45bbb8ba4912c9f191f3a82288e25bf41026de6e4`，与 `hashlib.sha256` 本地值逐位一致。
  - 截图确认行样式从"未记录"的淡紫变回常规金色下划线；测试目录 `files/pytest_hash/`、5001 实例已清理（5000 用户实例未动）。
- 本次范围外（用户拍板选最小改法，A/B 方案未采）：列表不自动发现外部拖入的新文件（仍需切用户或刷页）；列表不做整体哈希轮询，因此"不点按钮"的行仍会停在"校验码未记录"。
