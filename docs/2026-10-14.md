## 转公开前脱敏：改成"回调重放"，工作区与历史同源（A-1014-1 前半）

- 问题：要把仓库从私有转公开。逐项扫描受版本控制的文件，查出四类会跟着公开的本机信息：① 局域网 IP（4 份 `docs/` + `design-archive/` 竞稿页，共 8 处）；② 真实登录用户名与第二个身份词（AGENTS.md、review-issues.md、6 份归档、2 处代码：控制台横幅与 logger 名；另散布在 10 个竞稿页的假数据里）；③ Windows 账户名与项目绝对路径（`design-archive/qfs-waterlilies/` 三份设计工具产出的 JSON 共 42 处 + 1 份 spec）；④ git 历史本身（见下一条）。
- 原因：归档当初按仓库规矩"验证要写实测数字"，把当时的真实 IP、用户名、本机路径直接写进记录；`design-archive/` 是整目录入库的，工具产物里的绝对路径没人看过。第一轮我按"整词命中"手工点改，**漏了 10 个竞稿文件**（它们同样含真实 IP 与用户名），手工方式在这种分散场景不可靠。
- 解决方法：改为**规则回调**——一组按顺序生效的映射（IP→RFC 5737 为示例保留的地址段；两个身份词→假名 `用户`/`同事`；控制台横幅去身份化；logger 名缩短；家目录→`<HOME>`、项目根→`<PROJ>`；每条同时覆盖 JSON 双反斜杠与纯文本单反斜杠两种落盘形态），先用它重扫工作区（改动 30 个文件），再验证：`git show HEAD:<文件>` 的旧内容过一遍回调，与扫描后的工作区**逐字节比对**，33 个抽样文件一致（仅 AGENTS.md / README.md / review-issues.md 三处差在我当天新增的章节，属预期）。
- 回调脚本放哪：**仓库外的本机临时目录**。我一开始把它写进 `tools/`，是错的——规则里的匹配模式本身就字面写着待清除的旧值（账户名、项目绝对路径、邮箱），提交进仓库等于把这些值重新公开一遍。写完立刻用"待提交内容里 grep 旧值"这一步发现并撤出。
- 为什么先验证这一步：重写历史要用同一个回调。若两套规则产出不同内容，历史与 HEAD 会出现裂缝，"脱敏"就变成半成品。回调本身也在这轮被抓出两处缺陷（双反斜杠少一层转义导致 JSON 路径没命中；替换串以反斜杠结尾被 `re.sub` 当转义起始）——没有这个对照测试就不会发现。
- 备份：改动前的 7 份文件 + 全历史 bundle 各一份（`%TEMP%\qfs-desensitize-backup\`、`%TEMP%\qfs-history-backup-20261014-135320.bundle`，13.8MB）。

## 遗留（挡住转公开）：git 历史仍含全部旧值（A-1014-1 后半，已拍板重写）

- 问题：上面只清了工作区。`git log --all -S<串>` 实测：三个不同来源的局域网 IP 各能从 4 个历史提交捞出、账户名 3 个、第二个身份词 4 个；且全部 53 个提交的作者邮箱是同一个真实 163 邮箱，其中 4 个提交署名还带真实姓名。
- 原因：git 存的是每个提交时刻的文件快照，改工作区只新增一个提交，旧 blob 原样留在对象库里。
- 方案（用户已拍板"重写历史、保留 53 提交"）：`git filter-repo` 2.47.0（已装进 `.venv`）用同一个回调逐 blob 重写全部历史，作者/提交者邮箱统一换成 GitHub 隐私邮箱 `<ACCOUNT>-Y@users.noreply.github.com`；重写后重跑判据确认零命中，再删旧 tag 重打。
- 影响评估：commit 号全变，三个 tag 要重打；远程已推过旧分支与旧 tag，需要 force-push 并先删远程旧 tag。当前成本最低——仓库私有、无协作者、只本机一份克隆。公开之后再改既要 force-push，已泄露的内容也收不回。

## 版本与发布规矩建立：tag / pyproject / README 三处对齐 + MIT 许可证

## README 加「安全边界」小节

- 问题：README 只有一句"服务不做鉴权，仅限可信局域网使用"。项目公开后陌生人会照着"快速开始"直接跑起来，一句话不足以说明后果。
- 原因：原文是给自用者的提醒，不是给新用户的警告。
- 解决方法：新增「安全边界（部署前请读这一段）」五条写实——无任何登录/权限校验（知道 IP + 5000 即可读走所有用户全部文件，用户名不是密码）；不要端口转发/反代/穿透/DMZ，跨网请改用带端到端加密的工具（croc、magic-wormhole）；HTTP 明文不加密；留言板全员可见且"删自己的"只是界面约定；文件落盘不加密，想对页面隐藏就给文件名加个点前缀（`safe_filename` 拒点前缀，列表与下载都取不到）。原「注意事项」里端口守门那条保留。许可证另起一小节指向 `LICENSE`。
