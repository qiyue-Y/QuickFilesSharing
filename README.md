# QuickFilesSharing

局域网留言板 + 大文件快传服务。Windows 电脑上启动，同一局域网的电脑 / 手机用浏览器打开即可互传文本与文件，无需账号密码，无需装客户端。

当前版本：**1.3**（版本号同时记在 git tag 与 `pyproject.toml`，规矩见 `AGENTS.md`「版本与发布」；许可证 MIT，见 `LICENSE`）

## 快速开始

1. 首次安装依赖（任选其一）：
   - `uv sync`（推荐，仓库自带 uv.lock）
   - `pip install -r requirements.txt`
2. 启动：命令行执行 `python http_messages_share.py`（建议用项目自带虚拟环境：`.venv\Scripts\python.exe http_messages_share.py`）；Windows 也可双击 `start.ps1`（一键启动 + 桌面快捷方式）
3. 启动后自动打开浏览器；控制台列出本机所有局域网地址（标"推荐"的是默认路由出口），其他设备访问 `http://<局域网IP>:5000`

Linux 服务器：`gunicorn -c gunicorn.conf.py http_messages_share:app`

## 功能

- **留言板**：全员共用一块板，随手贴链接 / 命令 / 文本；页面只展示最近 5 条，更早的留在数据库里不显示，5 秒内自动收到别人的新留言。长留言折叠到 10 行、末尾省略号，点「展开」看全文；自己发的留言带「删除」按钮，别人发的删不掉
- **大文件传输**：最大 30GB；上传 4 路分片并行，开始前自动检查服务器剩余空间（不够直接拒传，页面显示剩余量）；整个页面都是投放区，文件拖进来即可上传（弹窗开着时的投放除外）；**断点续传**——中断后重传同一个文件，服务端已收的合格分片自动跳过，只补缺的（续传窗口 = 24 小时清扫周期）；≤1GB 下载走页内并行分片（带进度和速度），>1GB 自动交给浏览器下载管理器接管（支持断点续传）
- **完整性校验**：每个文件记录 SHA-256（合并时顺带算；手动放进目录的文件由后台线程自动补算，请求线程永不整读文件）。点校验码打开弹窗：可**把下载好的文件直接拖进弹窗**，页面用内置的纯 JS SHA-256 现场算给你看并比对（≤2GB，✅/❌ 直说）；更大的文件弹窗也备好 certutil / sha256sum 校验命令与 curl / aria2 命令行下载命令
- **分享链路**：顶栏地址芯片显示并复制的就是局域网 IP（本机用 localhost 打开也会换成真实 IP，发给别人直接能用）；「二维码」按钮离线生成带用户名的访问二维码，手机扫码直达登录页并自动预填用户名——链接带 `?u=<用户名>` 同样预填，登录页用户名留空则以 `default` 进入
- **传输可取消**：上传 / 下载均可中途取消（危险操作统一走页内确认框，不用浏览器原生弹窗），分片自动清理（启动时也会清扫超过 24 小时的残留分片，逐条记日志）

## 目录说明

| 路径 | 用途 |
|---|---|
| `assets/` | README 用的界面截图（不参与运行时） |
| `clipboards/messages.db` | 留言板（SQLite，WAL；开着库时同目录会有 `-wal` / `-shm` 附属文件）。旧的 `clipboards/<用户名>.txt` 已不再被读取，内容一次性导入后改名 `.migrated` 留在原地 |
| `files/<用户名>/` | 上传的文件；`.chunks/` 为分片临时目录（每轮上传含 `meta.json` 记录文件名与开始时间，24h 自动清扫）；`.hashes.json` 为校验码记录 |
| `logs/app.log` | 运行日志（20MB × 5 滚动） |
| `review-issues.md` | 问题清单：状态总表 + 已完结表 + 待实施正文（问题 / 解决方案 / 重要性 / 影响评估） |
| `docs/YYYY-MM-DD.md` | 按日期归档的改动记录（问题 / 原因 / 解决方法 / 日期，含实测验证） |

## 注意事项

- 用户名仅限字母 / 数字 / 下划线 / 连字符 / 中文，**不含空格和点**；用户名即存储目录名
- 端口固定 5000，启动时若发现已被占用（多半是旧实例没关）会拒绝启动并提示排查命令
- 局域网 HTTP 下浏览器禁用剪贴板 API 等安全特性，页面已做 `execCommand` 兜底

## 安全边界（部署前请读这一段）

本服务**设计上就是无鉴权的局域网内部工具**，不是面向公网的产品。它防不住任何已经在同一网络里的人：

- **没有任何登录 / 权限校验**：同网段设备只要知道服务端 IP 和端口 5000，就能打开页面、看到并下载**所有用户**上传的文件（用户名不是密码，任何人可以填任何用户名）。
- **不要暴露到公网**：不要做端口转发 / 反向代理 / NAT 穿透 / 放 DMZ，也不要在公共 Wi-Fi、机房共享网段上裸跑。需要跨网传输请换用带端到端加密的工具（如 croc、magic-wormhole）。
- **传输不加密**：局域网 HTTP 明文，链路抓包即可还原内容与文件名。
- **留言板是全员的**：所有人可见，「删除」只能删自己发的那条；但用户名是自填的，这条限制只是界面上的约定，不是安全边界。
- **文件落盘不加密**：`files/<用户名>/` 就是服务器上的普通目录，服务器上的任何账号都能直接读到。想对页面隐藏某个文件，给它加个点前缀即可（`safe_filename` 拒绝点前缀名，列表与下载接口都取不到）。

结论：**只在你自己信任的局域网里用**。加鉴权、加加密不在本项目的取舍范围内，这条边界不会通过加功能来改变。
